# Exercise 4 (hard): an upstream-quality PR description

Write the description you'd attach if you proposed your kernel to vLLM (don't submit it unless you decide to). Use these sections:

- **What & why:** one paragraph. The problem it solves, with numbers.
- **Design:** algorithm, launch configuration, dtype handling, numerics (and why the residual is bit-identical).
- **Correctness:** which tests, which shapes and dtypes, which tolerances and where they come from (P5.5 exercise 3).
- **Performance:** micro and end-to-end tables, hardware, versions, run-to-run variance, and the cases where it's *slower*.
- **Risk:** hidden sizes beyond the shared-memory limit, non-contiguous inputs, CUDA graphs, AMD/ROCm, and what falls back to the old kernel.
- **Alternatives considered.**

Then read two merged kernel PRs in vLLM's history and list what their descriptions have that yours doesn't.
