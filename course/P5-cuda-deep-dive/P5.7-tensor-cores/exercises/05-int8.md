# Exercise 5: INT8 GEMM with `dp4a` (and IMMA) (T2)

`d4::igemm_dp4a` computes int8 × int8 → int32 with `__dp4a`: four 8-bit multiply-adds in one instruction, on the regular CUDA cores. B is stored **transposed** (N×K), the layout quantized weights usually have, so both operands are contiguous in k.

1. Run `int8_gemm` and compare its TOPS with fp32 SGEMM rung 6 at N = 4096. The simple 32×32-tile kernel won't show dp4a's full 4× advantage. Register-block it the way rung 5 did for fp32, and re-measure.
2. *(stretch, sm_80+)* Use the tensor cores' int8 path: `mma.sync.aligned.m16n8k32.row.col.s32.s8.s8.s32`. The fragment layouts differ from fp16's, so look them up in the PTX ISA. Compare with `cublasGemmEx(… CUDA_R_8I … CUDA_R_32I, CUBLAS_COMPUTE_32I …)` (it has its own alignment and layout requirements, UNVERIFIED: read the cuBLAS docs).
3. Connect to P2.5: which quantized serving path (W8A8, W4A16) uses which of these instructions, and where does dequantization happen?
