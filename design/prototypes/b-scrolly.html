P1.2 · Prototype B: scrollytelling

The model that refused to read twice

Scroll. The picture on the right is a tiny language model generating text. Each step of the story changes it, from the generation loop to the memory bill that decides how many people one GPU can serve.

STEP 1 / 8

Generation is a loop

The model takes every token so far and predicts one more. Append it, call the model again. Five words means five calls.

STEP 2 / 8

Every token makes a key and a value

Inside each attention layer, each token is multiplied by learned matrices to make a key ("what I contain") and a value ("what I hand over"). The newest token also makes a query ("what I'm looking for").

STEP 3 / 8

The new token looks back

The query is compared with every earlier key. Softmax turns the scores into weights (line thickness). The output is the weighted sum of the values.

out = Σ softmax(q·kᵢ/√d) · vᵢ

Tokens only look backwards. So an old token's key and value can never change.

STEP 4 / 8

Without memory, everything is recomputed

A naive loop forgets. Every call rebuilds every key and value from scratch, in every layer. The red chips are pure repetition: identical numbers, computed again.

STEP 5 / 8

Keep them: the KV cache

Store each key and value the first time. Now a call computes one new key and value, appends them to the shelf, and reads the rest. Work per token drops from growing-with-length to constant.

STEP 6 / 8

Prefill: the whole prompt at once

The prompt is known up front, so all its tokens go through the model in one pass. Each weight read from memory is reused by every prompt token: the GPU is busy computing. This pass ends at the first output token (TTFT).

STEP 7 / 8

Decode: one token per pass

After that, each pass makes one token. It still reads all the weights (the grey block) and the whole cache, for a single token's worth of math. The GPU mostly waits on memory. The gap between tokens is the ITL.

STEP 8 / 8

The memory bill

Each token's cache costs 2 × layers × kv_heads × head_dim × bytes. For Llama-3-8B in bf16 that's 128 KiB per token, 1 GiB per 8k-token conversation. Watch users join until the 24 GB GPU is full.
